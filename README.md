# 随手新建

独立实现的 macOS 桌面与 Finder「新建文件」二级菜单。使用 Apple 的 Finder Sync 扩展与原生 AppKit，不依赖 REA，不包含其他 App 的代码或资源。

Apple Silicon 安装包可从 [GitHub Releases](https://github.com/haojiakui/suishou-newfile/releases/latest) 下载；源码构建方法见下文。

## 使用

1. 将「随手新建.app」拖入「应用程序」文件夹，然后双击打开。
2. 点击应用里的「打开 Finder 扩展设置…」，在系统设置中开启「随手新建」。macOS 26 中入口通常位于「通用 → 登录项与扩展 → 扩展 → Finder」。
3. 在桌面壁纸空白处，或进入普通 Finder 文件夹后在空白处右键，选择「新建文件 → TXT」等类型。也支持右键单个文件夹，在该文件夹内部创建文件。
4. 桌面或普通文件夹创建后，都会直接进入新文件的名称编辑框。输入名称后按回车确认，默认保留扩展名；桌面保持原位，不打开桌面目录窗口。已有同名文件时，创建「未命名 2.txt」「未命名 3.txt」，不会覆盖原文件。

首次使用自动编辑文件名，需要在「系统设置 → 隐私与安全性 → 辅助功能」中允许「随手新建」。开启后从菜单栏退出并重新打开应用，再使用右键新建；未授权时会在创建文件前提示。

macOS 也可能询问是否允许「随手新建」控制「访达」，需要允许。可在「系统设置 → 隐私与安全性 → 自动化」管理此权限；拒绝时文件可能已创建，但无法选中并进入名称编辑框。

应用驻留在菜单栏。关闭说明窗口不会退出；菜单栏可以重新打开说明或退出。

系统中若还有「超级右键」等同类应用，可能出现多个「新建文件」入口。本应用的类型名称带有 `(.txt)`、`(.docx)` 等扩展名。

类型菜单使用 macOS 提供的文件图标并保留原有颜色，外观取决于本机安装的应用和文件关联。Office 与 WPS 入口创建相同的标准格式，因此可能显示相同图标；菜单图标不会改变文件的默认打开方式。

## 文件类型

| 菜单 | 实际文件 |
| --- | --- |
| TXT | 空白 UTF-8 文本 `.txt` |
| RTF | 含有效 RTF 头的空白 `.rtf` |
| XML | UTF-8 声明与根节点 `.xml` |
| Word / WPS 文字 | 空白 OOXML 文档 `.docx` |
| Excel / WPS 表格 | 含一个空白工作表的 `.xlsx` |
| PPT / WPS 演示 | 含一张空白幻灯片的 `.pptx` |
| Markdown | 空白 `.md` |

WPS 入口创建标准 Office 格式，不生成旧版 `.wps` / `.et` / `.dps`。应用不会更改系统默认打开方式。使用「从模板创建…」可以选择自己的普通文件，按原始字节复制；模板支持零字节以外的任意文件内容，不支持文件夹包。

「自定义创建新文件…」接收带扩展名的名称；`.rtf` / `.xml` / `.docx` / `.xlsx` / `.pptx` 使用对应的有效内容，其余扩展名创建零字节文件。为特定应用创建文档时，应使用其有效模板。

## 架构

```text
Finder 右键菜单
    → Finder Sync 扩展获得明确的目录 URL
    → 自定义 URL Scheme 将类型与目录交给主程序
    → 主程序使用空白模板，以排他写入创建文件
    → 桌面通过 Finder selection 原位选中；普通文件夹由 Finder 显示并选中
    → 核对目标与 Finder 焦点，向 Finder 发送一次回车进入原生文件名编辑框
```

桌面使用当前登录用户的真实 Desktop 目录（同时注册其解析后的路径），避免误用扩展沙盒中的 Desktop。

扩展是沙盒进程，不读取文档内容、不扫描目录、不设置角标。主程序只在用户操作时创建文件，不联网。桌面选中通过 AppleScript 设置 Finder 的 selection 并将焦点交还 Finder；文件名通过 Apple Event 参数传入，不拼接到脚本源码。普通文件夹通过 Finder 的 reveal 命令显示并核对选中路径。辅助功能用于读取 Finder 的选中项和文件名输入框状态；编辑按键定向发送给 Finder 进程，发送一次后仅等待结果。连续创建请求依次处理，因为它们共用 Finder 焦点。自定义 URL 入口仅接受预设动作和绝对路径，不能覆盖已有文件。

## 构建

最低系统目标 macOS 13，交付构建适用于 Apple Silicon。本机需要 Apple Command Line Tools 和 Swift；不需要完整 Xcode。

```bash
bash Scripts/build.sh /absolute/path/to/empty-build-directory
bash Scripts/test.sh
```

`Resources/Templates` 已包含生成好的空白 Office 模板，构建不依赖 Python。模板最初使用 python-docx、openpyxl 和 python-pptx 生成；包内模板是新建的空白文档，不是从其他 App 提取。

默认使用本地 ad-hoc 签名。有 Apple 签名证书时可通过 `NEWFILE_SIGN_IDENTITY` 环境变量选择签名身份；公开分发还需要按 Apple 流程完成签名与公证。

## 验收范围与限制

- 自动化覆盖：主线程/后台菜单请求、跨进程菜单 tag、10 个类型、文档字节、中文和特殊字符路径传递、菜单映射、重名保留、非法文件名、无扩展名文件、隐藏文件、缺失模板、非法 URL、32 次并发创建。
- 模板验证：ZIP 完整性、XML 结构、python-docx / openpyxl / python-pptx 重新读取。
- 本机已验收扩展启用、Finder 空白处右键展开、真实点击 TXT、重名创建及 Word 文件生成。1.0.5 在真实桌面右键及普通目录中验证了自动进入文件名编辑框、输入中文、回车后磁盘名称更新；桌面未新增目录窗口。Office/WPS 实际打开与文件夹上的右键入口仍需验收。
- 使用本地 ad-hoc 签名，没有 Developer ID 和公证。macOS 是否允许加载扩展由本机安全策略决定，不能承诺在其他 Mac 上直接运行。
- 搜索结果、最近使用等没有明确可写目录的位置不提供创建入口；多选文件也不提供创建入口。
- 受保护文件夹、只读磁盘和网络卷受到 macOS 权限与文件系统约束。写入失败时由系统错误对话框显示原因。
- 本版实现截图红框中的「新建文件」，不包含常用目录、隐藏文件、终端和磁盘扫描功能。

## 移除

先在系统设置里关闭「随手新建」Finder 扩展，从菜单栏退出应用，再删除应用。应用没有登录启动项或后台 LaunchAgent。
